## HIGH

**H1. `sweep_date(inputs=...)` (subsample path) is broken in both directions** — `experiments/sweep.py:127-133` (`tickers = inputs.get("tickers", di.tickers)`, `probs = build(di, mandate, **inputs)`).
`restricted()` returns tickers as its 6th element, and the docstring says `inputs` overrides "B, F, d, S, adv". If the caller puts `tickers` in `inputs`, `build()` raises `TypeError: unexpected keyword 'tickers'` (reproduced). If they omit it, `tickers` falls back to the full-universe `di.tickers` while `nz` has length n_sub, so `record()`'s `np.asarray(tickers)[nz]` raises IndexError (or, if lengths happen to match, silently mislabels).
Scenario: C3 subsample sweep at N=100 → crash or wrong names in weights. No sweep test uses a subsample.
Fix: pop `tickers` from `inputs` before `build` (and require it when `inputs` is non-empty), or make `sweep_date` take `idx` and call `restricted` itself; add a test running `sweep_date` with `subsample(date, 100)` and checking weights' tickers ⊆ selected names.

**H2. `check_envelope.main` rebuilds the wrong universe for subsample runs** — `experiments/check_envelope.py:73` `subsample(..., row.get("N_label", "full"))`.
Sweep rows carry `"N": P.N`, not `N_label`, so `row.get(...)` always returns "full".
Scenario: points from a subsample sweep are rebuilt on the full universe; stored shadow price is for a different problem → `within=False` → S2 reports a failed self-check (or silently compares against the wrong problem).
Fix: store the subsample label in `ids` (e.g., `n_label` = "full" or the int) or recover from `N`; add a round-trip test (sweep at N=100 → `rebuild` → assert `P.N == row N`).

**H3. P-MI incumbent value V can exceed the feasible optimum, breaking the "V ≤ U\*" premise of the certified interval** — `src/opt/integer.py:~155-160`: `use_pol = ... U_pol >= U_inc; V = U_pol if use_pol else U_inc`.
When `U_inc > U_pol`, V is taken from `exact_objective(r.w, …)` at Gurobi's raw incumbent weights, which are only feasible to Gurobi's FeasibilityTol (1e-6) and (perspective) the cone tolerance; nothing checks they are feasible. If the incumbent sits 1e-6 over a binding style/beta/gross row (or violates w ≤ u·z), U(w_inc) is slightly above the true value at that z.
Scenario: V overstated by ~shadow-price × 1e-6 with no feasibility check on `w_incumbent`; L = (V₊ − B₋)/(2δ) can be inflated → false "binding" certification (δ ~ 1% of a bound of 0.01–0.05 makes a 1e-6 shadow-price error / 2δ non-negligible). `test_incumbent_value_bound_and_feasibility` only asserts the tautology `V == max(...)`.
Fix: when polish succeeded use `V = U_pol` (exactly feasible by construction) and record `U_inc` only as a diagnostic; if you keep max, accept `U_inc` only when `pmi_violations(w_inc, …, tol)` is empty at a tolerance tighter than the solver's. Add a test with a monkeypatched incumbent that is 1e-6 infeasible and assert V ≤ U_pol.

**H4. `open_run` resume ignores `status` and `extra_meta` of the new call** — `experiments/common.py:~107-121`.
Matching is on (config hash, commit) only; on match it returns the old `meta`, so the old `finish_status` and any CLI args stored via `extra_meta` (dates, workers, `--n`) are kept.
Scenarios: a `pilot` invocation (`status="pilot"`) in a dir with an unfinished "ok" run of the same name resumes it and `finish` logs "ok"; `--dates A` then `--dates B` at the same commit silently resumes the first run's directory and mixes chunks from different arguments into one `points.parquet`.
Fix: include `status` and `extra_meta` (canonical JSON) in the resume key, or refuse to resume and raise on mismatch.

## MEDIUM

**M1. Clean-tree check doesn't cover the data of record** — `experiments/common.py:~29-35`. `.gitignore` excludes `data/raw/` and `data/processed/`, so edits there leave `git status` clean, and `run_meta.json` records commit but no data hash. `MANIFEST_data.json` is tracked but never compared against the processed panel at run start.
Scenario: a stale or rebuilt panel gives different numbers under an identical commit/config hash and the run is resumed/recorded as reproducible.
Fix: in `open_run`, store `panel_sha256` and the risk-model hash from `build_meta.json`, compare them to the manifests (or call `tools/verify_data` logic) and refuse on mismatch; also check them on resume.

**M2. `finish`/`fail` can leave inconsistent state (contradicts "DONE + RUN_LOG + exit code agree")** — `experiments/common.py` `finish`, `fail`.
`finish` writes outputs and DONE, then calls `log_end`; if `log_end` raises (missing row, empty/malformed CSV → `rows[0]` IndexError), DONE exists but the row stays "running". A crash mid-output-write leaves a partial `<name>.parquet`; on resume `finish` hits `FileExistsError(out)`. `fail()` after a successful `finish` raises KeyError (row no longer "running"), masking the original error, and leaves both DONE and FAILED in the dir; `latest_done` only checks DONE, so it returns a run that also has FAILED.
Fix: write outputs to `.tmp` and rename; call `log_end` first or make `finish` all-or-nothing; have `latest_done` also require no FAILED; make `fail` tolerant of a missing "running" row.

**M3. `fail()` makes crash-resume practically unreachable** — `experiments/common.py` `open_run`/`fail`. The module docstring promises "a crashed run resumes in the same directory", but `open_run` skips any dir with a FAILED marker, and any runner that catches the exception and calls `fail()` marks the run FAILED — so only a kill -9 (no marker) can resume. `test_failed_and_pilot_status` asserts exactly this non-resume, so this may be intended; if so, fix the docstring; otherwise add a `--resume-failed` path.

**M4. `latest_done(name)` returns the newest DONE dir regardless of status** — `experiments/common.py` `latest_done`. It doesn't look at `finish_status` ("pilot") or RUN_LOG "superseded".
Scenario: `make figures` or a downstream table silently reads a pilot or a superseded run if it's the newest.
Fix: filter on `run_meta["finish_status"] == "ok"` and honor superseded markers.

**M5. `RUN_LOG` update is a non-atomic read-modify-write** — `experiments/common.py:~83-98`. `log_end` reads the whole CSV then replaces it, while `log_start` and `utils.append_run_log` append.
Scenario: two runners (`make -j`, or a runner plus `check_envelope`) overlap → a row appended between read and `replace` is lost (violates rule 7).
Fix: `fcntl.flock` the log around every access; have `check_envelope` write a "running" row at start.

**M6. `certified_interval` / `CertifiedSlope` accept NaN silently** — `src/opt/certified.py`. If V is NaN (no incumbent) or B is NaN, L/H are NaN; `binding` → False (read as "non-binding"), `solver_error` → False, `contains` → False.
Scenario: a work-limited solve with no incumbent is recorded as "not binding".
Fix: raise on non-finite inputs, or add a `valid` property and make `binding` return None/raise when not valid.

**M7. `sensitivity.fd_slope_rb` / `bound_value` silent-NaN and zero-step paths** — `src/opt/sensitivity.py:~40-92`. `bound_value` returns NaN for non-common bounds, then `fd_slope_rb` computes `h = rel_step*nan` → NaN slope with no error. Bound = 0 (dollar=0, beta=0, style=0, all on the C2 grids) gives `h=0` → ZeroDivisionError; bound = inf (the "off" single-style value) → NaN. `bound_value(problem, "position")` does `float(None)` → TypeError when u is None (the "off:position" problem keeps liquidity). The envelope check avoids these by filtering value > 0 and finite, but direct callers don't.
Fix: raise `ValueError` for non-finite/non-positive `b0` and for NaN from `bound_value`; handle `None` caps explicitly.

**M8. `integer_violations` tolerances are tighter than Gurobi's feasibility tolerances** — `src/opt/feasibility.py:~85-100`. The checker uses tol=1e-7, while Gurobi's FeasibilityTol is 1e-6 and IntFeasTol 1e-5. With z rounded, a w_i ≈ 5e-7 with z=0 is Gurobi-feasible but flagged "linking"; `min_position` can be violated by up to ~1e-6.
Scenario: a legitimate P-MI solution is reported infeasible in `pmi_violations` at scale (tests pass because the small instances produce clean zeros).
Fix: use tol ~2e-6 for the linking and min_position rows (or pass the solver's tolerances explicitly), or run the integer checks on the polished w (exactly feasible).

## LOW

- **L1.** `src/opt/integer.py` `_shadows`: `assert set(TWO_SIDED) >= {"dollar","beta","style","sector"}` tests a module constant — a runtime tautology on every call; move it to a test or remove it. Similarly `test_incumbent_value_bound_and_feasibility` asserts `r.V == max(r.U_incumbent, r.U_polished)`, which restates the implementation; replace with an independent check (see H3).
- **L2.** `src/opt/feasibility.py:84-85`: `cap * (zp+zm)` is `inf*0 = nan` when no caps are set; this emits a RuntimeWarning and `np.max` over the nan is order-dependent. In practice the other linking terms catch the cases that matter (probe: `{'linking': 0.05}` either way). Use `np.where(z>0.5, |w|-cap, 0)`.
- **L3.** `src/figures/make_all.py` `_g`/formatting: rounding is inconsistent (`round(…,10)` for BorrowBp/TradeCostBp/MiqpPositionPct but not for the `100*x` macros, so a config value like 0.07 would print `7.000000000000001`); `BaseBeta`/`BaseStyle` use `:.2f`, which silently rounds 0.025 to "0.03"; a scientific repr like `1e-05` would leak into LaTeX. Use one formatter that rounds to 10 significant digits and rejects values it would truncate. `LambdaMin`/`RootRtol` emit `10^{-6}`, which needs math mode at the call site; wrap it as `\ensuremath{…}`.
- **L4.** `tools/spec_check.py` heuristics: `draft_markers` and the `\textcolor{red}` literal miss `\color{red}`, `\textcolor{red!50}` and `\textcolor{Red}`, so PR-5 and RP-8 can pass with red text present; `forbidden_layout` ignores `\vskip -…` and `\setlength{\parskip}`. RP-11 returns WARN (never FAIL) when the `.log` is missing; in final mode `_build` creates it, so this is acceptable. `main()` truncates `detail[:w]` with w computed from the column, which is a no-op.
- **L5.** `tools/verify_data.py`: a missing manifest key (e.g., `panel_sha256`) raises KeyError instead of reporting FAIL; use `.get` and record a failing row.
- **L6.** `experiments/sweep.py`: `lam_base = solve_risk_budget(base, alpha, **rb_kw)` and the later `lam_guess=lam_prev, **rb_kw` raise "multiple values for keyword" if a caller puts `lam_guess` in `rb_kw`; pop it. `reset = restore` aliases a name kept only for v1 compatibility; keep it, but it hides that the restore also resets `position_caps`.
- **L7.** `src/opt/risk_budget.py` root-finder guard on the starting guess: `np.log(guess)` with `lam_guess <= 0` or NaN, or an all-zero alpha (unconstrained λ = 0), raises or returns nan/−inf; validate it. Minor: the slack branch decides "slack" only from vol at λ_min = 1e-6, which matches the docstring.
- **L8.** `src/opt/integer.py` `choose_s_obj` docstring says "in [1, 100]" then "[1, 10)". The code returns [1, 10), a subset of DESIGN's [1, 100], so K8 is fine; make the docstring consistent.
- **L9.** `experiments/common.py`: `finish`/`fail` re-resolve `ROOT` defaults at import, which is fine. `open_run` creates the directory before computing `provenance()`, so an ImportError leaves an orphan dir without `run_meta.json`, which is skipped on resume but never reported.

## Verified OK
- **`solve_qcqp` dual scaling and units.** The risk-row dual → μ_risk mapping is correct for all four forms (η/(2σ²), η/(2σ), η/σ², and the unnormalized quadratic), and unscaled duals = dual/s. σ_m = 0.03/√12 is consistent with `ann_vol = √(12·var)`, `unconstrained_lambda`'s 2σ_m, and `net_alpha`'s monthly borrow and κ; annual and monthly units are consistent throughout.
- **Root-finder bracketing and termination** are correct in every case: converged at x0, step up, step down, slack at λ_min, `_Converged` raised inside `brentq`, and Brent finishing without meeting rtol (loud RuntimeError). The `max_solves` cap prevents runaway loops, the `evals` cache keys are consistent, and `evals[x_min]` always exists on the slack branch.
- **Closed form and decomposition.** `closed_form.equality_case` satisfies KKT (ν, g, μ, w, A\* = σ_m√(g'Σ⁻¹g)), and the retained fraction equals √(g'Σ⁻¹g/α'Σ⁻¹α). With A = B', g = α⊥ (the B'Σ⁻¹ ∝ B'D⁻¹ argument) and TC = √(1−φ); the α⊥/α∥ split is Σ⁻¹-orthogonal.
- **Certified interval.** L = (V₊−B₋)/2δ, H = (B₊−V₋)/2δ and s are correct; the validation `not delta > 0` also handles NaN.
- **Toy closed forms** are correct (value, jump at ℓ, big-M/perspective (a−λdℓ below ℓ)/fixed-integer slopes), and the tests compare them against Gurobi to 1e-8.
- **P-MI scaling and the miqp additions.** Only α, λ, borrow and κ are scaled, and the shadows are divided by s_obj. `root_bound = −OBJBND` has the right sign for a max problem and is unscaled in `PMI.solve`; `work_limit` → `WorkLimit` and `WORK_LIMIT` is added to the status names. `exact_objective` matches the model's objective for w₀ = 0, and `relaxation_duals` reuses bounds via deepcopy.
- **Snapshot/restore.** Both bounds and `position_caps` are restored, including on exception; `fd_slope_rb` restores after each side and in `finally`; `sweep_date` records shadow prices before `reset` (the K12 fix); `effective_mandate` handles the off-position/off-liquidity problems and per-factor style bounds.
- **`tree_is_clean`.** Modified, staged and untracked non-ignored files outside results/ all count, and the exclusion pathspec works. Run directory names with the `_k` suffix sort correctly, and the `write_chunk` write-once rule is enforced.
- **Feasibility additions.** The risk row, linking, one-sidedness, min-position sign conventions (ℓ+w for shorts) and the cardinality count are correct. The checker shares no code with the optimizer (enforced by a test), and the kept `violations` behaviour is unchanged.
- **Tools.** `page_count.py` exits non-zero out of range; `make_all` is deterministic and hashes its sources; `spec_check`'s section, citation and allow-list logic is consistent with DESIGN §13 as written.
- **Tests that do their job.** K4/K6/K7/K8/K9/K10/K12/K13 compare independent computations (Clarabel vs the dual-simplex QP, closed form vs numerics, central differences vs duals, and the negative control for K12); the 189 tests pass.
