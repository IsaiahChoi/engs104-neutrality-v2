## MEDIUM

### M1. K29c (ii) silently leaves the 2017-12 style:Mom key ungated, and K29b does not cover it
File: `experiments/run_k29c.py` (`k8_pairs`, about lines 167-190); `experiments/run_i1.py:210-225` (`k29b_instances`).
Issue: a key is gated only if its elasticity at s_obj is finite and >= 1e-4. If the stencil at s_obj
fails, `e` is NaN, `key_gated` is False, and the key drops out of the scale comparison with no
verdict impact. This happened: the one failed gated stencil in the K29c run is
`2017-12 / s=1e4 / style:Mom` (reason "gap"). That key is an I1 constraint (Mom at 0.025). K29b then
checks only the first three I1 instances by sorted id, and all three are 2009-03 (f = 0.25, 0.5, 0.75).
So the scale-invariance of the perspective slope for Mom at 2017-12, and at 2020-03 in K29b, rests on
no gated comparison, although I1 reports it. `summary.json` lists the failed stencil, which satisfies
CHECKS (iii), and `tools/k29c_read.py` lists it, but the verdict does not flag it.
Failure scenario: a scale-dependent slope for a binding key at a date that K29b does not sample goes
unnoticed.
Affects s3_analysis.json: possibly `i1.errors_*` and `i1.k29b` (K29b `n` = 12, all from 2009-03). Today
the I1 relaxations all succeeded (0 of 240 failed) and the K29b max ratio is 1.1e-3, so there is no
evidence of an actual error.
Fix: have `summarize` report the number of keys ungated because the s_obj stencil failed. Say so in
PROGRESS and the report, or compare the 10x and 100x scales for that key anyway.

### M2. `tools/s3_analysis.py` has no tests
File: `tools/s3_analysis.py` (`i1_analysis`, `i2_estimators`, `i2_analysis`, `n1_analysis`, `n2_analysis`, `k26`, `_load`).
Issue: `tests/test_s3_analysis.py` covers the `src.analysis.s3` helpers only. Every headline number in
`s3_analysis.json` passes through untested glue:
- the filters `rel_delta == 0.10`, `presolve == -1` and `scale_factor == 1.0`;
- the join keys in `i2_estimators`, which uses `np.isclose(atol=1e-15)` and raises if the match count
  is not 1;
- the I2 secant construction, which assumes uniform spacing via `isclose`;
- `k26` string matching on `"{}"`;
- the hash check in `_load`.
Failure scenario: a config change (for example rel_delta 0.1 stored as 0.1000000001, or a new
presolve default) empties a filter. The result would be a zero-row summary, which `_q` and
`error_summary` report as n = 0 or NaN without raising.
Affects: potentially all numbers. Currently verified by me as sane (36 main-delta cases, 144 pairs
per the DESIGN counts of 108 + 36 solves, and 48 per pair).
Fix: add a small synthetic-frame test for each `*_analysis` function and assert the expected
non-empty sizes. Raise if a filter yields 0 rows.

### M3. Latent `NaN -> True` in `.astype(bool)` on possibly-missing flags
Files: `src/analysis/s3.py:64,66,99-100` (`persp_ok`, `binding`), `:224-226` (`k27`: `within`, `kink`),
`:250-251` (`k29b`: `persp_ok_k29b`), `tools/s3_analysis.py` (many `.astype(bool)`).
Issue: `pd.Series([np.nan]).astype(bool)` is True. A missing `within`, `persp_ok` or `pass` is read as
"ok". Today upstream filters prevent it (K29b is restricted to rows with a finite scale; `within` is
set wherever the slope is finite), but K27 relies on an implicit invariant.
Fix: use `.fillna(False)` or assert no NaN before casting. For `within`, treat NaN as a violation
rather than a pass.

### M4. Silent pass paths in the gating helpers
- `k24` (`src/analysis/s3.py`): `r["perspective"] > r["bigm"] + tol` is False when the big-M value is
  NaN, so a missing big-M relaxation would count as no violation and would not be counted as failed.
  Only perspective failures are excluded and counted. Add `n_bigm_missing` (currently 0 of 36).
- `k22` `_pairs`: a pair with finite V but an infinite or NaN B is classed "undefined" and skipped.
  A WORK_LIMIT stop with B = inf is then not tested, although V_i <= B_eff,j is a real test of the
  other arm's bound. Currently n_undefined = 0.
- `run_k29c.verdict`: toy points of kind "unchecked" (kink on both sides, or a stencil leg invalid)
  have `pass = None` and are dropped from `toy_points_checked`. The count appears in the summary's
  `kinds` (0 today), but the verdict does not require `unchecked == 0`.

### M5. Supplier statistics are vacuous for V
Files: `tools/s3_analysis.py` (`suppliers`); `experiments/run_i1.py` (`solve_point`).
Issue: in the I1 and I2 runs `v_tie` is true at 144 of 144 and 82 of 82 points and `v_from` is always
`bigm`. The "an exact tie in V goes to big-M" rule decides everything, so estimator (b) (the
fixed-integer dual) is always taken from the big-M incumbent, and "who supplied V" carries no
information. Not a bug, but a report statement of the form "V was supplied by X" would mislead. The
report should say that the two polished values were identical at every point.

## LOW

### L1. `raw_dual_rel_err_binding` mixes steps and usability
`tools/s3_analysis.py` (`rawerr`): it uses all `est` rows (both rel_delta 0.10 and 0.05, n = 34) and
includes raw duals marked unusable. Every other I1 statistic is main-delta only (n = 23). The label
says "binding" only. Restrict it to `main_est`, or rename it and report the split by `persp_raw_usable`.

### L2. B_eff slack floors the reported gaps
`final_gap_eff = (B_eff - V)/|V|` is >= 1e-6 by construction (observed minimum 1.0e-6), so Table III's
median certified gap is floored at 1e-6 for solves that closed the gap. Intended per DESIGN, but
label it as B_eff-based, and do not compare it with MIPGap 1e-4 as "the achieved gap".

### L3. K29b instance selection assumes aligned lists
`experiments/run_i1.py:instance_ids`: ids are built from `cfg["i1"]["K"][ym]["K"][i]` indexed in step
with `cfg["i1"]["f"]`. The realized `inst.K` from `s3.instance` is used for task ids. There is no
assertion that the two agree. If they diverge, `k29b_instances` selects ids that never occur and K29b
silently gets zero rows. The analysis `instances` list guards this today (3 instances, 12 rows). Add
`assert iid in k29b` bookkeeping, or check in `main` that `|selected| == n_instances`.

### L4. `json.dumps(default=float)` in `tools/s3_analysis.py`
Any `np.bool_` leaf is written as 1.0/0.0, and `np.int64` is written as a float. The current leaves
are mostly Python ints, but a future numpy-bool field would be mistyped. Use a small encoder.

### L5. `tools/k29c_read.py`
It is the "independent" recomputation but has a hard-coded `s0 = 1e4` and `gated_s` (not read from
the config), an unused variable `N`, `assert` as a check (stripped under `-O`), no `__main__` guard
and no docstring beyond one line. It shares the same reading of the toy closed forms as the runner.
It confirms the arithmetic and the kind classification but not the spec interpretation.

### L6. Duplication and style
- `integer.PMI.solve` now computes both `incumbent_violations` (default tolerance, unrounded z) and
  `incumbent_verdict` (1e-6, rounded z) on the same raw incumbent. Document which one K26 uses
  (`incumbent_verdict`).
- `run_i1.solve_point`: `name = lambda ...` (E731) and a dict-of-everything return; consider a dataclass.
- `run_k29c.verdict`: `== False  # noqa`; use `~checked["pass"].astype(bool)`.
- `fig_s3.fig4`: the unit factor `1e4*V` is labeled "bp/month". Confirm that V is a monthly return
  fraction in the alpha units (I could not verify this from the code alone).
- `fig_c.TAG = ""` renames the final figure files. Make sure `report/` includes and any stale
  `*_preliminary` outputs are not referenced (I did not check the report scaffolding).

- Not covered: `incumbent_verdict` with fractional z ("binary" key) and an incumbent just outside

## Summary
The numerical core is sound: the "design" slope rule, noise terms, and certified-interval and B_eff
formulas match DESIGN §6, and the K22–K29b helpers implement the CHECKS wording, including the
two-way K22 test and the K29b tolerance at s_obj. I found no wrong formula, wrong join key,
off-by-one in the stencil, or sign error that changes a number in `s3_analysis.json`, and the
counts reconcile (48 I1 cases, 144 points, 240 stencil relaxations, 144+3 N1 solves, 48 pairs per
arm pair). The risks are evidential and structural. The one K8 gated stencil that failed leaves the
2017-12 Mom scale check untested while K29b samples only 2009-03 (M1); the aggregation script is
untested (M2); a few filters and casts can fail silently if inputs change (M3, M4); and the V-supplier
statistic is vacuous because V ties in every I1 and I2 solve (M5). None of these blocks acceptance.
